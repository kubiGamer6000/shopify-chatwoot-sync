# Dashboard App (Customer 360)

A [Chatwoot Dashboard App](https://www.chatwoot.com/docs/product/others/dashboard-apps/) embedded as an iframe in the agent's conversation view. Built with React + Vite + Tailwind + shadcn/ui in [`web/`](../web/) and served by Express at **`/app`**.

> This is the agent-facing, per-conversation panel. The separate, standalone system-management UI is the [Admin Control Dashboard](admin-dashboard.md).

## What it shows

- **Customer header** — name, email, phone, default address (full country name), Shopify Admin link.
- **Summary** — total orders, lifetime value, subscription-order count, active subscription count.
- **AI Summary** — collapsible AI-generated recap (see below).
- **Response Composer** — AI reply generator (see below).
- **Orders tab** — every order with a derived delivery-status badge, financial status, subscription tag, line items, Shopify link, and a collapsible live-tracking section (17track).
- **Subscriptions tab** — Skio subscriptions with status, interval, products, next billing date, and a Cancel button (with confirmation). Prices display in each subscription's own `currencyCode`.

If the contact exists but no Shopify match is found, a simplified view still renders (header + AI summary + composer).

## Customer AI Summary

Each incoming customer message also generates a concise customer summary stored in Firestore (`customerSummaries`, keyed by Chatwoot contact id). Generated by [`src/services/customerSummary.ts`](../src/services/customerSummary.ts):

- **Overview** — 2-4 sentences: who the customer is, orders, lifetime value, subscription status, recent order states (each order line includes derived delivery state + tracking, so status isn't guessed).
- **History** — one structured entry per support conversation (id, date, status, detailed recap). Internal private notes / AI drafts are ignored.

A refresh button regenerates on demand (`POST /app/api/summary/refresh`).

## Response Composer

A compact composer powered by the same model, context, and playbook as the auto-draft. Uses the same three-field structured output as [AI drafts](ai-drafts.md#structured-output-three-fields):

1. Prefills the editable reply box with the latest stored draft.
2. Takes a free-form instruction and **Generate**s a reply (`POST /app/api/draft/generate`).
3. Iterates: a correction + **Regenerate** sends the prior reply + correction as a follow-up turn and replaces the text in place.
4. Shows `noteToAgent` in a separate "not sent" box, and any non-English `customerMessageTranslation` in its own read-only block above the reply.
5. **Send message & resolve** posts the reply to the customer and resolves the conversation (`POST /app/api/draft/send`).

## How it gets context

Chatwoot pushes the active conversation/contact to the iframe via `window.postMessage` (`appContext`). The SPA requests context on mount, listens for updates, and reacts to conversation switching. Customer resolution mirrors the draft flow: `shopify_email_link` → `shopify_customer_id` → contact email.

## Data flow

```
Chatwoot iframe ──postMessage(appContext)──▶ Dashboard SPA (/app)
                                                   │ GET /app/api/customer  (x-app-token)
                                                   ▼
                                      Express ─▶ Shopify (orders + delivery status)
                                              ─▶ Skio    (subscriptions)
                                              ─▶ 17track (optional live tracking)
```

Aggregator: [`src/services/customerProfile.ts`](../src/services/customerProfile.ts). Shopify/Skio/tracking reads are cached ([caching-and-storage.md](caching-and-storage.md)).

## Auth

Gated by a shared secret in `DASHBOARD_APP_TOKEN`:

1. **Page load** — Chatwoot loads the iframe with `?token=<DASHBOARD_APP_TOKEN>`; without a valid token the server returns 401 and does not serve the SPA.
2. **API calls** — the SPA reads `?token=` and sends it as the `x-app-token` header; `/app/api/*` rejects requests without a match.

If `DASHBOARD_APP_TOKEN` is unset, both are left open (with a warning). The `/app` routes also set `Content-Security-Policy: frame-ancestors` so only Chatwoot can embed the app.

## Local development

```bash
cd web
npm install
npm run dev      # Vite dev server (postMessage features only work inside Chatwoot)
```

For production it is built to `web/dist` and served by Express; the root `npm run build` builds it automatically.

## Register in Chatwoot

**Settings → Integrations → Dashboard Apps → Add a new dashboard app**, set the URL to `https://<domain>/app?token=<DASHBOARD_APP_TOKEN>`, save. A new tab appears in the conversation view.
